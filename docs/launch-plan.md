# Developer preview launch

Before announcement, require green source tests, offline demo, Docker Compose smoke and promtool fixtures on the release commit. Review capture/privacy boundaries, JSON-only transport, process-local cache limits and confidence/noul language. Verify repository security reporting, license and clean-checkout instructions.

Message: “OpenSpanGuard adds quality signals to original AI spans on the OTLP export path, then exposes coverage and cohort alerts in your existing Prometheus/Grafana workflow.”

Show the offline demo, original trace and coverage dashboard. Label synthetic scores and timings. Explain remote content transfer and opt-out. Position the small integration component beside existing platforms, not as their universal replacement.

Prepare a GitHub release note, technical post and walkthrough. Maintainers choose publication timing and channels; automation does not message people or post to communities. Advertise packages/images only after their artifacts exist.

Invite reproducible sanitized integration reports, never real customer prompts or keys. Prioritize correctness, privacy and export failures. Track first-week installation failures and first-month canary results. Publish measured results with environment/methodology, including negative findings, before choosing expansion targets.
